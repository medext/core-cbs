## Fixed rules (binding from Phase 3)

- **Versioning:** URI-based `/api/v1/…`; breaking change ⇒ new version; deprecation policy
  below.
- **Tenancy:** every request runs in an explicit tenant context (resolution per deployment
  config); URLs never contain guessable cross-tenant IDs (opaque UUIDs).
- **Idempotency:** `Idempotency-Key` header **required** on all financial writes; semantics
  per ADR-0006 (replay original / 409 on payload mismatch / retryable conflict in-flight).
  Client guidance: *always retry with the same key*.
- **Errors:** RFC 9457 problem details + stable machine-readable `code` from the
  [error catalog](error-catalog.md); `retryable` boolean; `correlation_id` echoed.
- **Money on the wire:** decimal strings + `currency` per ADR-0004; excess precision rejected.
- **Collections:** cursor pagination (`limit` ≤ bounded max) for financial collections;
  filtering via documented allow-lists only; stable sort keys. *As built (OD-26 resolved):
  parties, accounts and transactions lists use opaque cursors (`cursor`, `limit` ≤ 200,
  ordering `-created_at, -id`); the account statement uses a posting-id cursor (`after`,
  `limit` ≤ 200, response `next_after`); the small, bounded product catalog and the audit
  listing keep page-number pagination (`page`, `page_size` ≤ 200).*
- **Correlation:** `X-Request-ID` accepted/generated, propagated to traces, logs, audit.
- **Auth:** OAuth2 bearer; scope + permission documented per endpoint; 401 vs 403 semantics
  fixed (403 never confirms resource existence cross-tenant — 404).
- **Safety:** no unbounded request bodies; strict content types; write endpoints reject
  unknown fields (`400 VALIDATION_ERROR`).

## Backward-compatibility policy

Non-breaking (allowed in-version): new optional fields, new endpoints, new enum values
**only where catalog marks the enum open**, new error codes. Breaking (new version): removing/
renaming fields, changing types/semantics, tightening validation on existing inputs, closing
an enum. Deprecation: announced in docs + `Deprecation` header ≥ 6 months before removal;
policy details finalized Phase 5. Contract tests enforce this against the last released
schema.

## Sections authored with the implementation (MVP track, 2026-11-25)

1. **Resource model & naming** — plural nouns under `/api/v1/`: `parties`, `products`
   (sub-resource `versions/{n}`), `accounts` (sub-resources `balances`, `statement`, `limits`,
   `history`), `transactions` (operation collections `deposits`, `withdrawals`, `transfers`;
   sub-resources `transitions`, `reversal`), `holds`, `loans/{id}/disbursements|repayments`,
   `ledger/*` (read-only), `operations/*`. Nesting depth ≤ 2. No trailing slashes.
2. **Endpoint shapes** — `GET` collection / `POST` collection (create, 201) / `GET {id}` /
   `PATCH {id}` (parties only) / **action sub-resources** as `POST {id}/<verb-noun>`
   (`submit`, `approve`, `reject`, `retire`, `status`, `blocks`, `kyc`, `capture`, `release`,
   `reversal`, `simulate`). All MVP operations are synchronous; the async 202 + status-resource
   pattern is reserved for bulk/queued work (not built).
3. **OpenAPI 3.1** — generated by drf-spectacular from serializers and `@extend_schema`
   annotations (OD-6), served at `/api/schema/openapi.json` (Redoc at `/api/schema/docs`),
   committed as `docs/api/openapi.json`; a contract test fails when the committed file drifts
   from the generated schema. Key request bodies carry examples.
4. **Collections** — Postman/Bruno collections: not generated yet (Phase 10).
5. **SDK examples** — curl quickstart in the [API reference](api-reference.md); executable
   flow in `tests/e2e/test_api_flows.py`. Python SDK quickstarts: Phase 10.
6. **Webhook consumer guide** — see [event standards](../events/event-standards.md); HTTP
   webhook delivery is deferred (OD-30).
7. **Rate limiting** — not implemented (`RATE_LIMITED` reserved in the catalog).

Errors: every error — domain, validation, 401/403/404/405/415 and unexpected — is rendered by
one DRF exception handler in the RFC 9457 shape of the [error catalog](error-catalog.md)
(OD-27 resolved). Full endpoint list: [API reference](api-reference.md).
